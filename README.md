# 分流体检 / Route Monitor

运行在 Mac mini 的局域网分流观察工具。先监控、给建议，**没有修改规则、切换节点或发布订阅的功能**。

## 无 SSH 安装

1. 将 `RouteMonitor-macOS.zip` 传到 Mac mini，解压。
2. 双击 `安装.command`。首次填写路由器 API 地址（默认 `http://192.168.31.1:9999`）、现有代理管理密钥，再设置一个单独的页面访问密码（至少 12 字符）。输入密钥和密码时终端不会显示字符。
3. 浏览器会打开 `http://localhost:9780/`。用刚设置的页面密码登录。
4. 在其他设备使用 Mac mini 的局域网地址访问，例如 `http://192.168.31.81:9780/`。

安装包含 Apple Silicon 与 Intel 通用可执行文件，不需要 Python、Node、Go 或 SSH。配置和密钥在目标 Mac 上输入；包内不含任何人的配置、浏览记录或凭据。二进制是本地开发签名，未经 Apple 公证；若 macOS 要求确认开发者，需用户在系统界面处理，不应关闭 Gatekeeper。首次局域网访问若受系统防火墙阻止，需允许该程序的本地连接。

安装为当前用户 LaunchAgent：登录 Mac 后启动，退出登录后停止；休眠期间无法采集。不自动改变 Mac 的休眠设置。程序不应暴露公网，也不配置端口映射。

## 看什么

- 从 Mihomo `/connections?interval=5000` WebSocket 接收连接快照；以连接 ID 去重。
- 从 `/logs?level=warning` 接收警告日志。不改变路由器日志等级。
- 历史保留 7 天，页面展示最近 24 小时最多 300 个域名（优先错误数），筛选、详细错误记录、手动复测。
- 实际出口保留 DIRECT / JP / HK；未识别的出口记 OTHER。设备以本机实际记录的源 IP 标识。
- 核心只报告外层 SubRules 时，展示原始外层规则，不能声称已知道子规则里的具体命中项。
- 连接计数不是请求数；错误计数与连接计数不是同一分母，不能算失败率。连接长时间存在不等于访问慢。
- 未识别域名和未解析警告分别计数；不保存原始日志、URL 路径、Cookie、业务请求内容。
- 绕过代理核心的设备不在覆盖范围内。5 秒快照之间结束的短连接可能遗漏；断网、休眠时无法补抓历史。

## 复测与建议

复测由新错误触发或由用户手动开始，每轮 9 次测速调用：DIRECT、JP、HK 各 3 次。调用路由器 `/proxies/{name}/delay`，所以真正的出站请求发生在路由器。测试前读取 JP/HK 当前手动选择的叶子节点，不临时切换 selector。不支持自动选择组或嵌套组以避免不确定出口。

只测试最近 24 小时实际观察到的合法域名首页；检查监控机和路由器 DNS 结果，拒绝私网、fake-IP 和保留地址，不跟随重定向。DNS/解析校验失败会明确拒绝，不降级为任意 URL 代理。域名的 DNS 记录可能随时间变化，检查不是固定解析到同一地址的保证。

测速 API 会更新对应节点的测速历史与健康状态，但不会写入规则或改变 JP/HK 的手动选择。复测期间继续采集真实设备的错误。Mihomo URLTest 直接调用适配器，不经过普通入站分流警告路径；只解析带有效客户端源地址和端口的结构化错误，忽略无来源的合成日志。最多同时复测一个域名；手动操作间隔至少 1 分钟，自动复测间隔至少 3 分钟。Mihomo 开启 unified-delay 时，每次测速内部可能发送两次 HEAD，因此每轮最多 18 次 HEAD；每日最多 12 轮自动测速，对应最多 108 次测速调用、216 次 HEAD。不修改此路由器设置。

- 直连 3 次失败且某个代理出口 3 次收到响应：建议检查代理规则，仍需在设备上验证业务。
- 直连及代理均收到响应，且直连三次总耗时超过代理 3 倍、总差超过 3 秒：可考虑代理。
- 只出现被动错误：仅标记为待复测，不自动断言需要代理。
- 当前只观察到代理出口的域名，不因直连测试失败而建议再添加代理规则。
- HTTP 403/405/500 等也可能被 API 计为收到响应；无法获得具体响应码。结果仅代表探测层可达与耗时，**不代表登录、视频或 App 业务成功**。网络故障与 API 自身故障分别记“探测失败”和“无法判定”。

## 本地文件与停止

数据：`~/Library/Application Support/RouteMonitor/`，目录权限 0700，配置 0600。
启动项：`~/Library/LaunchAgents/local.route-monitor.plist`。
页面密码通过 PBKDF2-SHA256（200000 次迭代、独立盐）保存；页面只在通过密码登录后提供记录。不向浏览器提供路由器密钥。局域网 HTTP 不提供传输加密，适用于可信家庭网络。

停止并取消本次运行：

```sh
launchctl bootout "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.route-monitor.plist"
```

再次启动：

```sh
launchctl bootstrap "gui/$(id -u)" "$HOME/Library/LaunchAgents/local.route-monitor.plist"
```

如需取消以后登录自启，可在停止后将该 plist 移出 LaunchAgents；历史目录可保留。升级重新运行安装脚本，保留配置及数据库。不提供自动清空历史按钮。

## 已处理与新错误（0.2.0）

域名行和详情中的“标记已处理”会将其从默认待处理清单隐藏；切换到“已处理”可查看，并可“恢复到清单”。已处理状态保存在本机 SQLite，重启仍保留，不删除原始错误和复测记录。

0.4.0起，仅新错误类型或出口会将域名带回待处理；已确认的同类重复错误、新连接、重复采样和手动复测不会重新打开它。新类型在同一秒出现也会识别。页面展示仍限最近24小时和每个视图最多300个域名，处理状态不随7天事件清理而重置。

Agent 可直接使用现有认证会话：

- `GET /api/state?view=active`（默认）、`view=handled`、`view=all`。每行包含 `handled`、`handledAt`、`errorRevision`、`newErrors`。
- `POST /api/handling`，JSON：`{"domain":"example.com","handled":true,"reason":"已核对，暂时保留现有出口","expectedErrorRevision":1}`。`handled:false` 撤销处理。错误修订号必须来自最新读取的行；期间若出现新错误，返回409，需重新读取并判断，不能盲目重试。
- 沿用 `/api/login` 及 HttpOnly 会话，同源校验不变。接口仅更改本工具处理状态，不更改路由器规则、节点、出口或订阅。

SQLite增量增加`domain_handling`，旧错误记录在首次打开时建立修订基线，之后仅对真正插入的新错误递增。并发标记与错误写入串行处理，防止旧页面误吞新错误。回退旧二进制会暂时忽略处理状态，但已有事件仍兼容；再次升级可恢复处理状态。

macOS 升级提示：当前安装包为本地签名。替换二进制后，系统可能重新要求“本地网络”授权；若命令行检查能通过、LaunchAgent 却报告网络不可达，应先检查系统隐私权限。不得通过修改系统权限数据库或关闭安全保护绕过授权；完成授权前保留旧版以继续采集，数据库与配置不需要重置。

### 错误分类修正（0.2.1）

只分析结构化日志中目标地址之后 `error:` 后的原因；域名、规则和策略名称不参与分类。原因中重复出现的主机名也不会因含 `dns`、`certificate` 或 `timeout` 等片段而误分类。DNS查询超时仍归为DNS解析错误，以区分解析阶段与连接阶段。

仅新捕获的错误使用新分类。旧历史未保存原始原因，无法可靠还原，保留原记录，不猜测重写；已处理状态也保持不变。

## 自动复测（0.3.0）

启用后，同一域名在10分钟内出现2次新实际错误，会自动进行一轮 DIRECT / JP / HK 各3次的对照测试。旧历史不会触发，重复事件不计数；标记已处理后需出现2次未确认的错误才满足门槛；已确认的同类重复错误不累计。以北京时间计，每天最多12轮，两轮开始时间相隔至少3分钟；连接、日志和存储正常且连接快照新鲜时才会启动。不增加路由器轮询，不自动改规则或选择节点。

每个域名只有一次自动尝试：开始前持久化占位，成功、失败、NXDOMAIN、私网拒绝或进程中断都不自动重试，重启、重新报错、标记或撤销处理也不重置。手动复测独立，可继续使用，不消耗自动配额；正在进行的一轮不会被抢占。配额或间隔等待结束后重新检查10分钟窗口，过期错误不触发。服务重启会把未完成尝试标为中断。

增量表 auto_recent_errors 仅保存新事件的触发窗口，auto_probes 永久保存每域名自动尝试状态；原事件、复测结果和处理状态不重写。7天清理仍仅影响普通历史，不重置一次性记录。GET /api/state 新增 auto 配额信息、行字段 auto（状态、开始/结束时间、原因）；页面列表和详情同步显示。

## 代理可达标记（0.3.1）

最新完整三路复测中，DIRECT三次明确失败，而JP或HK在同一节点三次均可达，列表和详情显示醒目的“建议走代理”，说明直连3/3失败及具体可达出口；两个出口均通过会同时列出。此类域名在待检查清单优先展示。当前仅观察到代理出口时显示“代理可达 · 已走代理”，不建议重复加规则。已处理清单保留“复测：代理可达”证据标记。

不完整批次、未知API结果、三路均失败、不同批次或节点混用不产生该标记。后续新一轮测试会重新判断，记录仍按现有24小时展示范围使用。标记仅为HEAD复测证据，不自动修改规则，不代表App业务成功。API行新增proxyEvidence（routes/time）和recommendProxy，Agent可据此识别。

## 处理原因与同类错误（0.4.0）

标记已处理必须填写1–300字处理原因，在已处理列表和详情中显示，并可编辑。历史标记没有原因时如实显示“历史标记，未填写原因”。原事件和复测记录保留。

处理时确认当时最近24小时已记录的错误类型及出口；后续同域名、同出口、同错误分类的重复错误继续入库计数，但保持已处理，也不累计自动复测触发门槛。不同设备或不同时间仍视为重复。只有新的错误类型/出口才重新回到待处理；一旦重新打开，后续重复不会把它重新隐藏。撤销处理会清除本次抑制签名和原因，恢复正常提醒。错误类型沿用结构化原因分类，未分类错误统一为“连接失败（未分类）”，不声称能够区分未保存的原始异常。

处理状态及签名不会随7天普通历史清理或服务重启重置。升级只为当时仍处于已处理的历史标记建立一次兼容签名，不自动处理待处理项，也不伪造原因。手动/自动复测不会改变处理状态。

POST /api/handling 的handled=true请求新增必填reason字符串，例如 {"domain":"example.com","handled":true,"reason":"已检查，暂时保留现有出口","expectedErrorRevision":1}。handled=false撤销无需reason。错误修订号仍校验全部新记录，包括已抑制的重复，以防编辑原因时吞掉并发的新类型；409时须检查最新记录后重新确认。GET /api/state行新增handledReason。
